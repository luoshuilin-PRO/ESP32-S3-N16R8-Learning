# 红名像素检测：快速采集实验版

独立于原 `vision-controller`，使用 Windows GDI 持续复用一块小截图缓冲区。沿用现有 B 板 VISION-FIRST 固件的 VC1 协议，不需要重新烧录。默认 ROI 来自 2026-10-09 的采集样本：1920×1080 显示器，`x=950, y=599, width=16, height=21`。只有实际游戏画面和显示器位置相同时才能直接使用。

## 运行

双击 `start.cmd`。其他电脑需 Python（带 tkinter）及 `requirements.txt` 依赖。先不勾选“连接 B 板”，点击“开始预览”，检查采集区域和掩膜。若显示器位置或尺寸不同，先“框选区域”或导入 `material-capture` 的桌面截图 JSON；导入会显示原始 RGB、HEX、HSV 取色点。取色仅供核对，HSV 阈值仍在界面里设置。

要实际输出时，B 的 COM 接电脑用于 VC1 串口指令，B 的原生 USB 接电脑用于 HID；A/B 原有鼠标、供电、8 根 SPI 和 GND 连接照旧。关闭占用 COM 的串口监视器，勾选“连接 B 板”，开始预览，然后点击“启用输出”并确认；窗口最小化三秒后才启用。F8、恢复窗口或停止预览会关闭输出。固定屏幕区域无法判断游戏失焦，切换应用前按 F8。

界面显示实际循环 Hz、截图 ms、识别 ms、采集开始到串口写入完成 ms、收到 ACK 的往返 ms。“写入完成”只说明字节交给串口驱动，不是 B 板 HID 已被游戏处理。这里没有自动保存游戏截图或串口日志。

## 样本与限制

新采集的 11 张裁剪 PNG 中，4 张“有红名”和 4 张“有干扰”均有同一个红名字形，3 张“无红名”没有红名字形。现有 HSV 规则在这批样本上是 8/8 命中、3/3 不命中；样本数量少、名字相同，不能据此推断其他怪物、颜色干扰或烟雾画面的误触率。“有干扰”样本不是“仅有红色干扰、没有红名”的阴性样本。

当前调试值：HSV H=3..12、S>=150、V>=140；红色至少 10 像素、面积占比不超过 65%、分布至少 5×3；1 帧确认，目标间隔 10ms。采样间隔只控制 PC 循环，B 板连续点击仍为按下 50ms、松开 100ms。参数修改后停止并重新开始预览才生效。ROI 过小或目标偏移可能漏检，HSV 阈值仍可能误报。

运行 `python -m unittest -v test_fast.py` 验证图片和协议逻辑。运行 `python benchmark_capture.py` 在当前桌面只读比较旧 Pillow 截图与新 GDI 截图；它不连接 B 板或点击。游戏中的首击和停止延迟仍需实际测试，截图基准不能代替端到端测量。
