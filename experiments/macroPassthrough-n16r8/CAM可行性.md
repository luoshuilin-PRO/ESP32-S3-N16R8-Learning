# C 板摄像头颜色触发扩展：可行性评估

更新：2026-10-08。学习状态：学习中；C 板实现与代码验证：未运行（未开发、未编译、未接线、未烧录）。
用户已购买第三方 ESP32-S3 N16R8 CAM + OV2640；实际到手板的型号、引脚和镜头仍需实物核对。当前 B 板已烧录 VISION-FIRST，使用电脑截图 + COM 指令，CAM 尚未接入。

## 判断

**固定相机和屏幕条件下，完成“局部颜色检测 → 板间信号 → B 板单击”的学习原型，工程可行性较高。**
但“细小红名始终可靠、低误触、目标消失即零延迟停止”的实用效果尚不能保证。当前先比较电脑方案的真实耗时与相机采集表现，C 板没有进行实现或烧录。

乐鑫 esp32-camera 官方驱动支持 ESP32-S3 和 OV2640，并列出 RGB565 等格式，因此有驱动基础；这不代表任意标为 S3-CAM 的板子引脚、镜头和固件配置相同。[官方驱动说明](https://github.com/espressif/esp32-camera)

## 提议结构

```text
鼠标 → A（USB Host） → 现有 SPI → B（USB HID） → 电脑
                                    ↑
                         GPIO 或独立 UART
                                    ↑
屏幕画面 → C（已购 S3-CAM + OV2640，待实物核对） → 局部颜色判断
```

C 是第三块独立板，处理摄像头采集与检测；不把摄像头接到 A 已使用的鼠标 USB Host 上。
C 拍摄的是屏幕光学图像，不是直接获得电脑截图或 HDMI 数据。基本运行可不依赖电脑识别程序、网络或 Python；调试预览可以用电脑辅助。
B 仍由原生 USB 输出鼠标。COM4 是电脑看到的 USB 转串口名称，不是 C 板上的接口名称；C→B 板间 UART 应另选空闲引脚，避免与 CH343 调试串口输出冲突。

## 识别条件

1. 相机位置固定、能对焦红名所在的小区域；确认镜头最近对焦距离和视场。
2. 先采集有红名、无红名、红色干扰背景的相机原始帧，不用电脑截图代替相机样本。
3. 在相机画面内重新标定 ROI，适当固定曝光/白平衡，测试屏幕亮度、刷新条纹、摩尔纹、反光和环境光影响。
4. 根据相机样本选择颜色范围、命中面积/比例和形状约束；颜色阈值不等于目标身份识别。
5. 连续新帧命中才允许输出，首个未命中或坏帧就撤销许可；停止路径不使用长时间防抖。

此前电脑截图讨论的 1600×900、ROI 720..880 / 450..570 和 RGB #F24A17，不能直接当作相机坐标与精确颜色值。
例如完整 1600 像素宽画面缩成相机帧宽 320 时，原 161 像素宽区域仅约 32 像素；细字可能已丢失，需要靠光学取景或提高分辨率解决，而非只扩大 HSV 容差。

RGB565 对颜色有量化，镜头、曝光和屏幕又改变颜色；必须标明颜色空间和数值范围。ROI 软件裁剪能减少检测计算，但不自动减少传感器采集/帧传输开销。
官方说明 RGB/YUV 采集对 PSRAM 带宽压力较大，Wi-Fi 并用更需注意；JPEG 后转换也是可选路径，但有解码成本。先在具体板卡上测帧率、坏帧及图像可用性，不预先承诺帧率。[驱动注意事项](https://github.com/espressif/esp32-camera#important-to-remember)

## 通信与停止

GPIO 电平可用于最简演示，但**不能只让高电平无限连点**：C 死机后输出可能卡在高电平。需要独立心跳或周期脉冲及 B 端超时。
更适合诊断的候选是独立 UART：新帧序号、命中/未命中、有效期及校验；只有新鲜有效帧才续期许可，旧消息或重复序号不能续期。
尚不固定最终协议字节、波特率、超时数值或 GPIO 号，待实测采样周期和板卡引脚确认。

```text
上电/重新连接 → 自动点击关闭
手动启用 + 新帧有效命中 → B 在许可有效期内按节奏输出单击
未命中/坏帧/关闭开关/通信超时 → 清除待执行自动点击并释放自动按下状态
```

每次单击必须包含按下和释放，有最短间隔、最长按下时间，不把高电平理解为左键一直按住。
新鲜帧持续命中才续期；停止命令优先处理，不允许积压的“单击命令”在目标消失后继续播放。
摄像头采集失败后不能重复把缓存旧图当新检测帧。即便加入保护，目标消失到停止仍有曝光、帧周期、处理、通信和 USB 延迟；已经发出的点击不可撤回。

## 与现有模式的关系

现有 B 固件已实现电脑视觉优先于炼狱/M4：识别命中时视觉独占左键，结束时恢复真实左键及手动模式；右键 USP 已移除。若改用 C 板，相机状态应接入同一优先级规则，但协议和接线仍需另行设计与验证。
B 的实际物理按键与自动按键状态需分开管理；停止自动点击不能误释放用户正在按住的真实左键。
应沿用默认关闭和急停能力。LED 指示方案也应避免与既有模式混淆。

**纯 C 板摄像头不能直接查询 Windows 活动窗口。** “窗口失焦立即停止”不是纯硬件方案天然具备的能力。
若这个条件必须可靠实现，需要电脑端提供焦点状态；若坚持不运行电脑程序，只能改为人工启停或画面条件判断，并明确它们不等同于系统焦点检测。

## 硬件前置条件

- 已有 ESP32-S3 N16R8 CAM + OV2640 商品与厂家资料；到手后核对实物板版本、正反面、原理图、摄像头与引脚表，不能直接套用另一版原理图。
- 采用合适且稳定的板级电源，核对实际输入规格；板间通信共地，不盲目并接多个 5V 电源。
- GPIO/UART 使用兼容的 3.3V 逻辑，不把 5V 电源接入信号脚。
- B 已用 SPI 39/40/41/42、10/11/12/13、USB 19/20、RGB 48；还需排除串口、启动绑带和存储器占用，不能因排针空着就认定可用。
- C 的摄像头占用较多 GPIO，最终引脚分配必须按具体板核对。
- 普通外置 LED 仍需串联限流电阻；通信模块是否需要另买取决于连接距离与电平，短距离同电平 UART 通常无需额外转换模块。
- 固定支架和可用焦距与板子本身同样重要。共享讨论提到的低速逻辑分析仪不能用来可靠采样当前 80MHz SPI，应按被测信号带宽选仪器或另行设计降速测试。

## 分阶段验收

| 阶段 | 验收证据 | 是否允许点击 |
|---|---|---|
| C 板采集 | 能稳定看到红名局部，记录分辨率、帧率、曝光和坏帧 | 否 |
| 离线检测 | 有/无目标与红色干扰样本的误触、漏检统计 | 否 |
| 连续检测 | 固定视角下实时结果，目标消失及坏帧能撤销命中 | 否 |
| C→B 通信 | 新鲜度、丢包、停止、断电及超时测试 | 否，先用日志/指示灯 |
| B HID 接入 | 空白测试环境验证单击、节奏和停止，不遗留按下状态 | 人工启用后允许 |
| 联调 | 测量端到端启动/停止延迟、误触率并确认可接受 | 通过前不声称可靠 |

## 当前需要用户提供

1. C 板到手后，实物正反面、版本、摄像头标识和镜头资料。
2. 能否固定相机只拍准星附近，实际距离、屏幕刷新率和亮度设置。
3. 是否坚持电脑完全不运行辅助程序；这决定窗口焦点检测的边界。
4. 后续确认点击间隔、最大可接受停止延迟、启停方式、与旧宏互斥规则。

## 是否能降低延迟

当前电脑路径：屏幕截图 → HSV 判断 → COM 串口 → B HID。候选相机路径：屏幕显示 → 曝光/取帧 → 颜色判断 → C/B 有线通信 → B HID。相机方案可省掉 Windows 截图与 PC 串口往返，但增加光学采集与板间通信；不能仅凭“硬件识别”推断一定更快。

帧率仅能换算帧间隔，例如实际 30 FPS 约 33.3ms/帧；这是计算例子，不是这块板已测值。官方驱动说明单帧缓存要等待 VSYNC 并取得整帧，较慢；双缓存连续取帧增加负载且建议 JPEG。颜色识别需实测帧的新鲜度、解码/计算开销、曝光时间和红名可读性。[官方驱动注意事项](https://github.com/espressif/esp32-camera#important-to-remember)

当前 B 固件视觉连点按下 50ms、松开 100ms，周期 150ms。换成 CAM 不会自动改变已开始连点时的点击节奏。下一步先记录现有软件的实际循环 Hz、截图识别耗时、串口往返耗时，并区分“第一次触发慢”与“持续点击下一个目标慢”；随后再用 C 板独立测首帧和连续新帧延迟，最后比较端到端首击与停止时间。没有这些实测，不给 CAM 承诺具体降幅。
