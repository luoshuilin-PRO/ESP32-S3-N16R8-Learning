## 当前固件用法

| 状态或操作 | 行为 |
|---|---|
| 上电 | 总开关关闭；除中键控制外正常透传 |
| 中键短按 | 开启/关闭；开启进入普通模式 |
| 开启后中键长按 800ms | 普通 → 炼狱 → M4 → 普通；每次长按只切一次 |
| 开启后的普通模式 | 左右键、移动、滚轮透传；侧键屏蔽，不执行宏 |
| 炼狱按住左键 | 左键按下 140–155ms，释放 20–30ms，松开停止 |
| M4 按住左键 | 左键按下 50ms，释放时向下移动 3 个相对单位，间隔 100ms |
| 炼狱/M4 按住右键 | USP：输出左键按下 38–45ms、释放 5ms，松开停止 |
| 关闭/普通模式右键 | 正常右键，不触发 USP |

炼狱/M4 中右键原动作被替代，不能同时用于右键瞄准。USP 优先于左键动作；USP 结束或模式切换后，已按住的触发键须先释放再按，不自动接续另一宏。中键不传给电脑。

鬼跳（Ctrl + 空格）代码及后退触发入口保留，但当前链路未识别侧键，不能把鬼跳列为可用功能。没有键盘 P 输出，没有 A-Z 演示宏触发。
M4 是固定相对位移，不识别武器或实际弹道，不保证游戏内效果。参数是目标间隔，USB/任务调度可能延长实际间隔。

## 板卡与接线

两块实测均为 ESP32-S3 QFN56 rev v0.2、40MHz 晶振、16MB Flash、8MB Octal PSRAM。

| 板卡 | 工程 | 历史串口 | 角色 |
|---|---|---|---|
| A | usb-input | COM3 / CH343 | USB Host 接鼠标，经 SPI 发给 B |
| B | usb-output | COM4 / CH343 | 接收 SPI，作为 USB HID 接电脑 |

串口号可能变化，烧录前用 esptool read_mac 核对板卡身份。设备完整 MAC 仅保留本地，不公开。
COM 是 USB 转串口，用于供电、烧录、日志；USB 是芯片原生接口。按丝印辨认，不依照片左右判断。

断电接线，两组 SPI 同号直连，MOSI/MISO 不交叉：

| 信号 | A GPIO | B GPIO | 用途 |
|---|---|---|---|
| MOSI | 39 | 39 | A → B HID 数据 |
| MISO | 40 | 40 | 第一组总线 |
| SCLK | 41 | 41 | 第一组时钟 |
| CS | 42 | 42 | 第一组选通 |
| MOSI2 | 10 | 10 | B → A 输出报告 |
| MISO2 | 11 | 11 | 第二组总线 |
| SCLK2 | 12 | 12 | 第二组时钟 |
| CS2 | 13 | 13 | 第二组选通 |
| GND | GND | GND | 公共地 |

共 8 根信号线 + 1 根地线。同板各 GND 共地，不必每个都跨板连接。当前沿用 80MHz SPI，杜邦线应短，信号完整性未专项验证。

```text
A COM ← 独立 5V USB 电源（需要日志时可接电脑）
鼠标 → OTG 转接头 → A 原生 USB
A ↔ 8 根 SPI + GND ↔ B
B 原生 USB → 电脑（HID）
B COM → 电脑（烧录/日志）
```

板间不互接 5V 或 3.3V。用户已确认仅 A 短接 USB-OTG 供电焊盘，B 未短接。
隔离烧录：全部断电，拆掉 B 板间线及原生 USB，只接 B COM；完成后全部断电再恢复接线。

## USB 供电与焊接

曾出现 A 板有电、鼠标不亮，用户测得 OTG 输出几毫伏；鼠标和转接头直接接电脑正常。
单板排针测得约 4.4–4.5V / 3.3V；B 5V 排针跨板供 A 曾导致电压下降，已弃用。鼠标灯亮只证明供电，不证明枚举或数据正常。

参考照片为 YD 系列 V1.3，厂家公开电路为 V1.4；布局相似不等于实物版本完全相同。V1.4 电路：

```text
COM VBUS -------- D1 ---> 板内 5V
原生 USB VBUS --- D2 ---> 板内 5V
5V 排针 --------- D3 ---> 板内 5V
```

USB-OTG 焊盘旁路 D2，使板内电源能够给原生 USB 的鼠标供电；IN-OUT 旁路 D3，是另一用途。
这解释了 COM 供电但原生 USB 不输出 VBUS 的现象。2026-10-06 用户确认 A 已完成 USB-OTG 短接、B 未改；焊后照片和 VBUS 带载电压尚未归档。

焊接核对流程（已焊好的板不要重复盲焊）：
1. 断开所有电源、鼠标和板间线。
2. 按原理图和通断测量确认 USB-OTG 两焊盘分别连原生 USB VBUS 和板内 5V，不是 IN-OUT、USB-JTAG 或电源排针。
3. 少量助焊剂、焊锡短时桥接，避免邻近连锡和长时间加热。
4. 冷却后确认桥接导通、对地无持续低阻短路；电容可造成短暂蜂鸣。
5. 先空载供电测 VBUS 和发热，再接鼠标测带载状态。

A 旁路后原生 USB 只接鼠标，不在 A COM 供电时再接电脑等有源端，以免回灌。不要给 GPIO 接 5V，也不要用 3.3V 代替鼠标 USB 5V。

## LED 与电阻

之前说的是普通外接 LED 的**串联限流电阻**，不是上拉或下拉电阻。每颗独立 LED 应单独限流，不把裸 LED 直接跨接 GPIO 和地。
阻值按电源电压、LED 正向压降、目标电流及 GPIO 允许驱动能力计算：`R = (V供电 - Vf) / I`，红黄绿蓝不应仅凭颜色共用一个未经计算的值。没有合适限流电阻时暂不接外置 LED。

本版使用 B 板现有 WS2812 RGB，按参考电路由 GPIO48 控制，不需要另接普通 LED 的串联限流电阻。参考电路中的 `RGB 0Ω` 是数据连接跳线，不是上述限流电阻；若实物未连通，需先核对再处理。不要把 RGB 焊盘和 USB-OTG 供电焊盘混淆。

| 状态 | 板载 RGB |
|---|---|
| 关闭/普通 | 熄灭 |
| 炼狱 | 亮 500ms、灭 500ms |
| M4 | 亮 2000ms、灭 2000ms |
| USP 执行 | 亮 100ms、灭 100ms |

使用低亮度绿色。电源指示灯不会随宏关闭；“RGB 不亮”不能区分关闭和普通模式，也不能单独证明固件故障。当前右键版灯效尚待用户确认。

## 2026-10-06 排错结论

| 现象 | 证据与结论 | 处理 |
|---|---|---|
| 旧版右键输出字母、移动鼠标 | 原项目带 A-Z 和移动演示宏，不是据此认定硬件故障 | 新版停用旧宏入口 |
| M4 下压太大 | 首版每次固定下移 25 | 当前改为 3，待实际手感反馈 |
| 侧键不触发、没有快闪 | 新版日志 enabled=0、blocked=0、neutral=0 时仍无侧键值；纯透传对照版也未记录到 | 不再盲改键位，采用右键 USP |
| 曾以为原版侧键正常 | 用户恢复原始演示版回测后表示此前混淆两只鼠标，当前原版链路也无前进/后退 | 更正早期“侧键已正常”的记忆；不据此宣称上游对所有鼠标都不支持侧键 |
| 接回后鼠标亮但无法移动 | B 反复报 SPI invalid `0; 0;`，用户万用表检查后确认接线接错 | 修正后恢复，日志出现左键 SPI/USB 收发 |
| 电脑第一轮检测没有任何事件 | 沙箱内连左键都没有；桌面权限运行后收到 B 左键事件 | 空日志不作为鼠标故障证据 |
| 偶发 TinyUSB 提交失败 | 旧版日志记录一次，代码尝试重新入队 | 不足以解释 SPI 层无侧键；队列压力未完整验证 |
| IDF 构建 WinError 5 | 沙箱阻止 CMake 子进程 | 经授权在沙箱外构建通过 |
| RMT 初始化警告 | 空配置结构体用 `{0}` 报多余初始化元素 | 改为 `{}` 后编译通过 |

侧键限制目前是这套固件、鼠标与连接的实测结论。尚未抓取 A 板完整 USB 原始报告并解析 HID 描述符，根因未精确定位，不将其归为已证实的 B 新版回归。
G502 老版滚轮上下/按下由用户此前反馈正常；另一只 Rapoo 鼠标滚轮上下曾无效，解析兼容性待查。不要把不同鼠标的结果混为一项通过。

## 源码与复现

`firmware/usb-input` 保留已适配 A 版；`firmware/usb-output` 更新为当前已烧录 RIGHT-USP 源码。
不复制多份过时工程：最初演示宏适配快照可在本仓库历史提交 `953b5bc46aeb8a0813dbb7ebf598862a24e2d0f4` 找到。上游 LICENSE 和 README 保留，上游 README 不代表本分支实测行为。
旧 macpass_macro.c 和宏表仅作参考，当前不编译旧宏实现，也不调用旧前后置钩子。

上游：[arfevrier/macroPassthrough](https://github.com/arfevrier/macroPassthrough)，原基线 `90d31a0f3c8b3a9587005d1f4a5bb67c319f57e2`。
本机使用 ESP-IDF `v5.4-dirty`，不是 5.5.4，也不代表所有 5.4 环境已验证。驱动安装提示未阻止已识别 COM 的烧录，未优先重装驱动。
适配保留：第二组 GPIO 10/11/12/13；16MB Flash、Octal PSRAM 40MHz；IDF 5.4 下 SPI 异常恢复用 free/等待 500ms/重新初始化；日志格式修复及 started 标记。
依赖固定 esp_tinyusb 2.2.0、tinyusb 0.19.0~3；当前 B FreeRTOS 1000Hz。

激活 IDF 并确认版本，在对应工程运行：
```powershell
idf.py --version
idf.py set-target esp32s3
idf.py build
# 核对目标板身份并隔离接线后，端口号按实际设备填写
idf.py -p COM4 flash
```
切换旧构建环境前按需 `idf.py fullclean`。A 使用其工程和实际端口，不能把 B 固件刷到 A。
不提交 build、managed_components、机器绝对路径、完整 MAC 或凭证。

## 尚待验证

- 当前右键版：普通拖动、炼狱/M4 左键、右键 USP 停止、模式切换、RGB 节奏。
- A 板焊后照片、VBUS 带载电压、实物 PCB 版本。
