## 1. 当前保留的成果与版本

- 本仓库：`ESP32-S3-N16R8-Learning`，本项目目录为 `experiments/hid-bridge-mouse-passthrough/`。
- 实机曾确认：双板实体鼠标透传、串口手动测试、OBS/NDI 画面传输、`cf.onnx` 识别。**当前最新版视觉程序→串口→A/M→B/P→另一台电脑实际 HID 动作尚未完整复测**。
- 当前 HID-Bridge 固件使用上游 **v0.1.2**，不是此仓库自行维护的固件分支。上游代码和版本：[ESP32-S3-HID-Bridge v0.1.2](https://github.com/guobaren/ESP32-S3-HID-Bridge/tree/v0.1.2)；[上游项目主页](https://github.com/guobaren/ESP32-S3-HID-Bridge)。下载、构建及烧录需遵照对应版本上游说明。当前仓库**没有提供可直接刷写的双板固件镜像，也未确认恢复时的镜像哈希**。
- 旧项目 `macroPassthrough-n16r8/` 的 A/B 源码与 SPI 接线属于**另一套历史方案**，不能当成 HID-Bridge v0.1.2 UART 固件互换刷入。

## 3. 已提交的程序入口

- `current/ndi-yolo-viewer/`：NDI 视频接收、YOLO 检测、可选 HID 控制。入口 `run.cmd` → `main.py`；同目录含 `requirements.txt`、README 及 `OBS使用说明.md`。其 `run.cmd` 要求先创建 `.venv`，缺少环境时不会自动安装。
- `current/hid-bridge-python/`：串口身份查询与手动输入测试；含 `main.py`、`run.cmd`、`requirements.txt`。
- `current/hid-bridge-diagnostics/`：独立的协议、串口、统计、启动日志诊断；含 `main.py`、`run.cmd`、`requirements.txt`。
- `previous/ndi-yolo-viewer/` 与 `previous/source-only.zip`：旧版源码留档，**不是完整离线安装包**。旧源码 ZIP SHA-256：`EE1FE3F03DD6CF46BBD40F8583215D3E683DFA30B7D11EB03E6F9C5E70BD85E6`。
- **目录相对位置很重要：** `ndi-yolo-viewer` 会引用同级 `hid-bridge-python` 的控制器模块，不要只复制视觉工具的单个目录来声称完整。

## 4. 从 GitHub 恢复的建议顺序（尚待新机实测）

1. 克隆本仓库，阅读本目录 README、当前三个工具各自 README 和测试总结。注意本仓库部分材料是历史 SPI 实验，不要混淆固件方案。
2. 检查两块 ESP32-S3 N16R8 身份、接线与现有工作固件；已经能透传时**不要为验证文档而重新烧录**。当前 HID-Bridge 板间是 UART：A/M GPIO17 TX → B/P GPIO18 RX，A/M GPIO18 RX ← B/P GPIO17 TX，GND ↔ GND；不互接 5V/3.3V。
3. 在 Windows 安装 Python 3.12 x64（带 tkinter）。按 `current/ndi-yolo-viewer/README.md` 建立 `.venv`、安装对应目录 `requirements.txt`；诊断/串口工具按照各自 README 安装。必要时安装 NDI Runtime、OBS 和发送插件，检查许可与兼容版本。
4. 由有权使用的模型持有者把 `cf.onnx` 放入 `current/ndi-yolo-viewer/models/`，使用 `Get-FileHash -Algorithm SHA256` 校验；缺模型时不能声称完整 YOLO 功能已恢复。
5. 先只读连接 OBS/NDI 来源、加载模型测试识别；再做串口身份/角色和 uptime 检查。串口只能由一个程序占用；诊断查询也可能切换固件的软件输入所有者。
6. 在目标电脑的空白测试窗口且用户明确确认后，分阶段验证鼠标输入：真实鼠标透传→手动命令→视觉输出；输出默认关闭。未确认前不要直接在游戏内启用。
7. 最后记录完整双机从目标出现到 HID 输入的首击延迟、误触、断流恢复与长时间稳定性；这些仍**未验收**。

## 5. 尚未完成、不得标为成功的项目

- 最新版视觉控制程序→串口→M→P→另一台电脑的完整端到端输入复测。
- 目标出现到实际 HID 动作的首击延迟、停止延迟及分段计时。
- 真实场景的识别准确率、误触率、长时网络/串口稳定性及 NDI 源重连。
- 全新 Windows 电脑从 GitHub 安装环境、获取自有模型并完整复现的冷启动验收。
- 已刷 M/P 固件二进制、配置、哈希的安全离线备份，以及模型/153 MiB 迁移包的私人异地备份。
- 第三方依赖与 NDI 运行库的具体分发许可复核。
