# NDI 视频接收＋YOLO＋可选 HID-Bridge 输出

2026-10-14 已恢复 OBS/NDI 入口和原有跟随行为，默认参数见 [当前使用说明](OBS使用说明.md)。保留模型格式检查和本地延迟统计，入口仍为 run.cmd，默认输出关闭。

默认只接收视频、显示检测结果、保存手动样本。新增输出需手动连接串口和单独确认启用；不修改现有 HID-Bridge 工具或固件。

## 新增鼠标输出（默认关闭）

先关闭旧版窗口，再启动 run.cmd；关闭 hid-bridge-python 和其他占用 A 板 COM 的程序。

1. 正常连接 NDI、加载模型、开始识别。
2. 刷新串口，选择 A/M 板实际端口（此前 COM3），点击连接／查询。固定 115200，签名＋nonce＋序号＋角色=2 验证后开放“启用输出”。这一步不发送鼠标报告，但 A5 查询会切换软件输入所有者。
3. “右键＋红名连点”默认勾选，“右键头部跟随”默认未勾选；这两个设置不等于输出已启用。
4. 检查主机窗口、松开物理左右键，点击启用输出并确认。启用时只验证 V4，不重新切换 A5；需要新鲜检测结果。
5. 按住真实右键、中心附近存在 class=1 头部框、固定区域红名命中才启动连点：默认按下 50ms、松开 100ms，约 6.67 次/秒。人物框覆盖中心不再单独触发点击。
6. 连续第 3 个新的红名结果未命中，释放软件左键；前两次漏检保持连点。重复读取同一结果不计为新帧。右键松开或头部丢失不经过三帧宽限，立即在当前逻辑轮停止；200ms 结果过旧、断流或停止识别关闭许可，恢复后需再次启用。右键松开保留全局许可，可再次按住触发。
7. 可选鼠标跟随只选最近的 class=1 头部框，没有头部不退回身体；默认范围 150 原始视频像素、比例 .05、单次 HID 步长最多 4。每个新结果仅移动一次，3 像素死区。类别筛选请留空或包含 1；主机鼠标灵敏度决定实际效果。
8. F8（副机全局按键）或“停止输出”撤销许可并释放软件按钮；退出和串口异常也尝试释放。副机 F8 不是通过两板接在主机的鼠标/键盘按键。

验收顺序：只读物理右键 → 跟随测试（点击关闭）→ 红名连点（移动关闭）→ 组合，每阶段单独询问用户。识别框可能误检，工具不分辨游戏阵营；class=1 头部只由样本支持，不代表训练标签已完全核实。游戏窗口失焦尚无跨电脑检测，切换主机窗口前必须先停止输出。串口断线时释放可能未到达，须在主机检查。

### 真实右键和协议

连接阶段仅一次 A5 DeviceProbe 验证 HIDBRDG2、nonce、序号及 M 角色，然后切到 V4。运行期查询 API 0x04、物理按钮 0x55；右键为 mask bit1。输出只用 V4 左键 SET 0x11 和移动 0x18，不穿插 A5、不订阅、不改波特率。独占 115200 串口，DTR/RTS 在 open 前后置低。查询会切换软件输入所有者，先关闭其他客户端。

物理查询目标每 20ms 一次，单次响应超时 80ms，状态有效期 120ms；只保留一个在途查询，超时不重试，避免无序号 V4 的迟到回复冒充新状态。检测到超时后撤销资格、释放并关闭串口。实际右键释放延迟还包含串口和线程调度，不保证零延迟。V4 SET 没有成功 ACK；只能记录写入，需在主机观察实际消费。已经排入固件的短移动不保证撤回。

经确认后的只读入口：`.venv\Scripts\python.exe check_buttons.py --port COM3 --seconds 30`，不发送移动或点击，保存 buttons-check.json。不要同时打开软件或其他 COM 工具。

### 红名区域

独立于 YOLO ROI，默认原视频 (268,377,90,24)、640×640。HSV（OpenCV）H=0..12、S≥150、V≥140；至少 20 像素、宽跨度≥12、高跨度≥3、面积占比≤65%。两张指定样本分别 316/0 像素，命中/未命中；未证明烟雾、不同距离或红色干扰下准确。

红名区域用橙色框显示，检测像素数显示在状态行。保存配置包含 red 字段，读取时验证；可在输出关闭状态调整 JSON 的 roi/hue_max/saturation_min/value_min/min_pixels。视频不为 640×640 会停止识别，需重新取材，不自动缩放固定坐标。

物理鼠标输入与软件输入由 HID-Bridge 固件合并；如果你一直按着真实左键，可能看不到软件释放造成的连点边沿。此版没有屏蔽物理鼠标或改变固件优先级。保持现有三线 UART 接线，不重新烧录。

按下／松开、旧帧超时、移动比例、步长和半径在启用时冻结；改参数后先停止再重新启用。更换模型、ROI、识别参数时自动撤销许可。输出许可和串口连接不保存在配置，不自动恢复。手动框选区域不会改变视频中心的判定位置。

## 运行

本机：双击 `run.cmd`，使用项目独立 `.venv`，Python 3.12 x64。

其他电脑：安装带 tkinter 的 Python 3.12 x64，执行 `py -3.12 -m venv .venv`，再 `.venv\Scripts\python.exe -m pip install -r requirements.txt`。不要同时安装不同的 onnxruntime 发行包到同一环境。

已安装：cyndilib 0.1.3、ONNX Runtime DirectML 1.24.4、NumPy、Pillow、OpenCV headless；运行不需要副机 OBS 全屏，副机 OBS 也不是本工具的画面来源。

## 视频与识别使用顺序

1. 主机 OBS 保持已跑通的 NDI 发送，副机与主机局域网互通。NDI 防火墙/网络设置沿用现有成功配置。
2. 点击“刷新来源”，手动选择主机，例如 `HOST (OBS PGM)`，点击连接。
3. 默认模型是复制到 `models/cf.onnx` 的用户模型。选择 DmlExecutionProvider、v5、类别数 2，点击加载。
4. 在预览上拖框选择识别区域，显示原始视频 x/y/w/h，不是 Windows 屏幕坐标。黑边不计入坐标。
5. 置信度默认 0.25；类别筛选为空表示全部，或填 `0,1`。点“开始识别”后参数生效；更改置信度/筛选后再点开始。
6. 停止识别只保留视频预览。断开停止识别和接收。配置可保存到 config.json；读取配置不自动连接或加载模型。
7. 可选静态图片测试，结果和标注图保存 samples。保存 PNG/结果则保存当前同帧原始图、ROI 图及 JSON，不持续录制。

## 模型边界

`cf.onnx` 来源为用户桌面文件，仅复制，原文件未修改；SHA256 为 `D8268E5268009761F7044EE3289B018E1487E64122C1CB124ADF2589111F2BEE`。模型许可及类别语义由用户确认，不随公开源码分发。

实测输入 images `[1,3,320,320]` float32，输出 `[1,6300,7]`，元数据 names `['0','1']`。结构符合 YOLOv5 原始输出（xywh＋objectness＋2 类概率），这里只能确认结构，不确认训练来源和类别含义。

只支持：
- v5：`[1,N,5+C]`，模型输入像素坐标 xywh、独立 objectness、类别概率。
- v8：`[1,4+C,N]`，xywh、类别概率，无独立 objectness。
- xyxy：`[1,N,6]`，模型输入像素 xyxy、score、class。

使用 RGB、letterbox 114、除以 255、NCHW float32、类别独立 NMS；不同归一化、坐标单位、后处理、多输出、分割、姿态或其他模型布局会被拒绝或需要另行适配。程序不会猜测并转换未知布局。动态输入默认 320，第一版需代码参数调整其他动态尺寸。

DirectML 支持 RTX 4070，选它是为了不额外部署 CUDA/cuDNN。也可手动选择 CPU。会话显示实际提供者列表；GPU 会话中的部分算子仍可能落到 CPU，列表不是“每个算子都在 GPU”的证据。默认不偷偷切换整个 CPU 会话。模型预热和输出检查会产生一次推理。

## 性能与断流

- 接收与推理独立线程，程序仅保留最新一帧和最新结果，不累计待推理队列。
- 接收请求 RGBX/RGBA，仍检查 FourCC、分辨率、真实行步长并复制像素，释放包装器缓冲。
- NDI 接收包装器还有内部及网络缓冲，本工具不能保证所有上游缓冲都是一帧。
- 2 秒无帧清空可识别画面；约每 5 秒尝试重新连接相同来源。回到有帧状态后继续原已启用识别。来源改名时重新扫描。
- 分辨率变化时，已有 ROI 停止识别并要求重选；全画面模式可继续。
- 检测框与产生它的原帧绑定，不叠到另一帧。结果过旧或断流不显示旧检测框。
- 推理耗时是本机 session.run 的墙钟耗时，可能受线程调度影响；处理耗时还含预处理和后处理。本地排队从本机接收返回到处理开始计算，不含发送电脑采集/编码、网络或解码等待。
- 接收 FPS 是本程序实际取到帧的速率，不是主机游戏 FPS；推理 FPS 是完成处理速率。
- 未做跨电脑时钟同步，不报告完整画面年龄，也不把这些数值称为端到端延迟。

## 依赖、源码和许可

- [cyndilib](https://github.com/cyndilib/cyndilib)：Cython Python NDI 接口，实际使用已安装 0.1.3 的源码/API，不依赖过时枚举示例。
- [NDI 软件分发条款](https://docs.ndi.video/all/developing-with-ndi/sdk/software-distribution)：本机已有 NDI 6 Runtime；NDI SDK/运行库是独立许可，不因 Python 接口开源而转为开源。cyndilib wheel 含运行库及对应许可，保留其许可；本项目不另复制系统 DLL。对外打包前需核对 SDK EULA、署名和第三方许可。本界面提供 ndi.video 链接。
- [ONNX Runtime DirectML](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html)：禁用 memory pattern、顺序执行；同一会话调用串行化。
- [Aimmy](https://github.com/Babyhamsta/Aimmy)：参考模型/置信度/区域/预览架构；其 C# 项目使用 .NET 8、WPF、ONNX DirectML。Aimmy 是 source-available，未移植或复制其实现。
- [HID-Bridge](https://github.com/guobaren/ESP32-S3-HID-Bridge/tree/v0.1.2)：保留其现有鼠标透传；本工具不导入它的串口程序。
