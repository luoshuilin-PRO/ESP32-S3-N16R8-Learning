# NONX 模型分类与按游戏导入

本目录有 90 个 ONNX 模型，按 44 个直接含模型的游戏文件夹分组。检查结果见 [模型清单](模型清单.md)；完整标签、形状、元数据和 SHA-256 见 `model-catalog.json`。检查阶段没有复制模型到 `ndi-yolo-viewer`，也没有修改该项目或运行游戏。

## 使用

1. 推荐把 `NONX` 放在项目内部，即 `ndi-yolo-viewer/NONX/`。也兼容旧的同级目录布局。工具按自身位置寻找项目，不依赖盘符、用户名或项目外层文件夹名称。换电脑后先在项目根目录运行 `install.cmd`，建立本机 `.venv`，再运行游戏目录中的导入入口。
2. 进入所需游戏文件夹，双击 `一键导入.cmd`。脚本只复制当前文件夹内的模型到项目 `models/NONX/对应目录/`；能由现有读取器解析的模型才生成 `profiles/NONX-*.json`。它不会连接 NDI 或串口，也不会启动鼠标输出。
3. 在项目运行 `run.cmd`，从「游戏配置」选择 `NONX-...`，切换后手动加载模型。新配置默认 CPU、关闭红名自动点击；需要 GPU 时在界面选择 DML 再加载。类别含义、敌我与头部索引需看模型标签并用实际画面验证，不能按文件夹名称推断。
4. 不再需要此游戏时，先关闭识别程序，再在原游戏文件夹双击 `一键取消导入.cmd`。脚本依据 `.nonx-imports/` 清单，只删除这次导入创建且哈希未改变的模型和配置；若文件被改过，会停止删除并报告。其他游戏或原有项目文件不受影响。

导入脚本要求目标路径不存在，不覆盖同名文件。重复导入会提示先撤销。`一键取消导入.cmd` 不恢复用户后来保存到其他路径的独立配置；若已修改导入的配置，应先自行留存，需要撤销时可还原原文件后重试。

只看计划、不复制任何文件：

```powershell
..\.venv\Scripts\python.exe .\import_manager.py import --group "cs" --dry-run
```

## 判定边界

- `family` 是架构代际判断：ONNX `description` 明确写出 YOLO 名称时为高可信；仅文件名出现 `v8` 等字样时标为 candidate；缺少证据时为 unknown。
- `layout` 是项目所需的输出解析方式，与 YOLO 代际不是同一件事。`v8` 布局只指 `[1,4+C,N]`，YOLO11/YOLOv12 也可能使用这种布局。
- 目前 83 个模型可生成现有项目配置：79 个 `v8` 布局、1 个 `v5` 布局、1 个 `yolox` 布局、2 个元数据标记 end-to-end 的 `xyxy` 布局。已全部通过当前电脑 CPU 加载、零输入推理及现有解析器检查，记录见 `compatibility-audit.json`；尚未逐个验证 GPU 和游戏内识别效果。
- `cs/CS2敌我.onnx` 已纠正为 YOLOX，依据三组 cls/reg/obj 检测头权重名称和项目既有同哈希分析。虽然输出宽度与 v5 相同，但其预处理和网格解码不同，不能按 v5 导入。现有项目已经支持 `yolox`，无需为它修改项目。
- 6 个三角洲 YOLO11 模型输出 `[1,N,4+C]`，现有 `detector.py` 缺少这类转置布局。另有 1 个 Apex 模型输出 `[1,N,6]`，无法仅凭形状区分单类 v5 与已做 NMS 的 xyxy。它们的文件可导入，但不会生成项目配置。要使用前六个，需要后续修改项目解析器；最后一个需先验证输出语义。
- `Apex英雄_20k_brock.onnx` 的静态输出维度均为符号值，已用 CPU 零输入验证实际输出 `[1,5,8400]`，因此按 `v8` 布局建立配置。
- 导入的配置不会自动设置专用红名区域，也不会自动启用跟随。不同游戏不应沿用 CrossFire 的固定红名区域。

迁移时完整保留项目内的 `NONX/`。若已执行导入，也要保留 `models/NONX/`、对应 `profiles/NONX-*.json` 和 `.nonx-imports/`；撤销清单记录的是相对路径，换盘符或电脑后仍可使用。请先完整解压再运行，不能直接在压缩包内操作。新电脑的 GPU、NDI 和硬件仍需现场验证。

如模型文件发生变化，使用项目虚拟环境运行 `inspect_models.py`、`generate_report.py` 和 `generate_shortcuts.py` 更新目录内清单与入口；该检查依赖 `onnx`、`onnxruntime` 和 `numpy`。日常导入与撤销仅需 Python 标准库。
