# 固件备份、烧录与恢复

入口：包根目录 start-firmware.cmd。首次运行自动安装依赖。使用固定 esptool 5.1.0 与官方 HID-Bridge v0.1.2 三段镜像，无需 ESP-IDF，不自动下载或升级固件。

## 操作顺序

1. 关闭识别、诊断和其他串口工具。一次只处理一块板，先断电拆除鼠标、原生 USB、外接电源和板间线，再仅用 COM 数据线连接电脑。
2. 向导选“备份并烧录”，指定板卡标签和当前 COM。刷写传输默认 460800，连接不稳定可重启向导选择 115200；这是传输速率，与固件运行串口及 Flash 80 MHz 时钟不同。
3. 核对提示，输入 ISOLATED 后才连接/复位进入下载模式。读取 ESP32-S3 型号、MAC、Flash 实际容量和安全状态；根据实际板子确认 BOARD A/B 和 MAC。
4. 自动备份整片实际 Flash；16 MB 板备份 16 MB。检查长度、SHA-256，并与板端摘要核对。备份失败时结束，不擦除。
5. 显示备份路径。输入包含板卡和 MAC 的 FLASH 确认词，才执行整片擦除、三段写入和独立校验。回车取消会保留备份。
6. 写入校验后复位、采集约 10 秒日志。报告区分 Flash 校验通过、启动证据和透传待验证；日志不足时不会把启动判为通过。
7. 结束后断电再接板间线和 USB。推荐先完成 B/P 板，再完成 A/M 板；两板刷同版本。

检查/备份操作同样会复位板子进入下载模式，并中断原透传；正常结束尝试复位回应用。连接失败可按住 BOOT，点按 RST 后松开 BOOT，再启动向导。擦除/写入过程中保持供电；失败报告中保留已验证备份，重新连接后可重刷或恢复。

## A/B 与接线

两板写同一份固件，A/B 标签用于记录物理板子，不是不同的固件文件。运行时固件按 USB 和板间通信协商 M/P。

- A/M：本项目这块板的背部 USB-OTG 供电触点已经短接，USB 接鼠标，COM 接运行控制程序的电脑。
- B/P：背部 USB-OTG 触点未短接，原生 USB 接接收鼠标输入的电脑，COM 为可选供电/诊断口。实际供电路径应按板型核对，避免外部电源互相回灌。
- A GPIO17 → B GPIO18；A GPIO18 ← B GPIO17；GND ↔ GND。不要互接 5V/3.3V，不使用旧 SPI 八根线。
- 软件不能自动判断焊点状态。这里的焊点说明只针对用户已确认的两块板，其他板型先核对原理图。

单板隔离时不验证完整角色协商、kmbox/Makcu 或鼠标透传。接好双板后使用 start-diagnostics.cmd；实体鼠标移动、左右/中键、滚轮、侧键仍须在接收电脑实测。

## 固件参数与备份恢复

官方清单为 DIO / 80 MHz / 4 MB，偏移 0x0、0x8000、0x10000。16 MB 是实际容量，4 MB 是这份固件的使用配置。清除的是 Flash 中的软件与 NVS；不写 eFuse。发现安全启动、加密或安全下载模式时，普通流程停止，不使用 force。

备份在 firmware-tool/backups/A或B-MAC-时间/，包含 flash.bin、backup.json；写入操作还包含 operation.json、boot.log。完整保留整个子目录，备份中可能含旧配置，适合私下保存。

恢复选择该目录下 backup.json，要求 MAC、容量、长度、SHA-256 均匹配。恢复前同样先备份当前内容，然后输入 RESTORE 确认词。原字节按 keep 参数恢复，不替换原固件的 Flash 头参数。备份不包含 eFuse，也不保证任意旧固件和未来硬件状态都可恢复。

本项目不自动制作迁移副本或压缩包。手动复制 `ndi-yolo-viewer` 时不要把私人备份、板卡 MAC 映射或日志作为通用安装文件传播；需要保留的备份单独妥善保存。

## 验证与许可

`main.py --self-check` 只核对镜像/依赖，不扫描或连接设备。`python -m unittest -q` 使用模拟设备验证失败与取消路径。开发本轮未连接实际板卡；新向导的实际备份、刷写及启动日志判定尚待实测。
