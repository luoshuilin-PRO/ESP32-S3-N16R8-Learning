# HID-Bridge Python 串口测试

仅 Python 手动诊断，不烧录、不运行视觉模型、不自动点击。副机连接 A/M 板 COM，真实鼠标已透传到主机。

## 运行

在项目根目录先运行 `install.cmd`，然后双击 `start-serial-test.cmd`。不要只复制本子目录；依赖与 Python 环境都在上一级 `ndi-yolo-viewer` 中。

启动入口使用项目本身的 Python 3.12 环境，不使用 ESP-IDF Python 或其他全局环境。

1. 关闭其他占用 A 板串口的程序。选择实际端口（本次用户确认副机 A 为 COM3，但程序不预选），M 默认 115200。
2. 点击连接，仅打开串口，不发送输入；再点击查询身份。只有有效签名、匹配 nonce/序号、角色 2（MOUSE_HOST）才开放输入按钮。
3. 读取统计，间隔数秒再次读取，检查 uptime 增量与墙钟一致。首次基线不证明未复位；固件版本不是 DeviceHello 字段，不伪造版本识别。
4. 主机打开空白测试窗口，松开物理鼠标按钮。每次移动或点击均弹出独立确认。
5. 停止中断动作等待，释放软件按钮。移动中停止不会继续回移；停止不是撤回已经发送的移动。
6. 断开或退出释放本工具注入状态；纯查询退出不发送释放报告。日志自动保存到 logs。

没有输入逐条 ACK；日志的 TX 表示串口写入，DeviceHello 表示身份响应，统计表示快照完整，均不证明主机实际消费鼠标报告。主机效果须人工观察。位移为相对单位，受系统加速度影响，不保证回到原坐标。

串口断线时释放命令可能未到达，工具会明确记录失败；请在主机检查按钮状态。固件自身租约是额外保护，不当作本工具释放已到达的证据。

## 协议依据与注意

- [HID-Bridge v0.1.2](https://github.com/guobaren/ESP32-S3-HID-Bridge/tree/v0.1.2)：bridge_protocol.h/c、uart0_control.c、tools/uart_protocol.py、tools/read_device_stats.py。
- A5 5A，版本 02，类型 u8，序号 u16le，长度 u8，最大 64 字节载荷，CRC16-CCITT（FFFF/1021）。使用 06/07 身份、1D/1E 统计、05 会话、02 鼠标、03 释放。
- M UART0 默认 115200，P 默认 921600；不自动试速或设置波特率。P/未知角色拒绝输入。
- 有效 A5 查询会选择 A5 软件输入所有者，可能清空其他客户端的软件输入并释放注入按钮。因此“只读”表示不注入鼠标、不复位，不表示绝对无状态变化。不要与 Makcu/Host 客户端交替争用。
- 打开之前和之后均将 DTR/RTS 置低；软件设置不能替代实机 uptime 连续性检查。
- [Aimmy](https://github.com/Babyhamsta/Aimmy) 的 .NET 8/WPF、ONNX/DirectML 架构仅作为未来参考，本工具未移植其代码、未加载模型。Aimmy 为 source-available，后续复用需检查许可证。

## 测试与边界

执行 `py -3 -m unittest -v`。自动测试覆盖模拟协议、分片、坏 CRC、角色拒绝、短写、停止、释放和异常；不证明真实 USB 消费、透传不中断或延迟。

实机身份、uptime、移动及点击均尚待验证；启动界面不会自动进行实机测试。两板供电焊盘和 UART 接法保持现状，不改固件。

本轮结果：16 项模拟测试通过；隐藏窗口启动、默认输入按钮禁用、工作线程退出检查通过；未打开 COM3，未发送实机输入。
