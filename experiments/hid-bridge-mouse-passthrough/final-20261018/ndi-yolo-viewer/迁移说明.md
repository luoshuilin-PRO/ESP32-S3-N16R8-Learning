# 迁移到另一台 Windows 电脑

## 可选 NONX 模型库

`NONX/` 现可直接放在本项目内部，随整个文件夹一起迁移。新电脑完整解压后先运行根目录 `install.cmd`，再进入 `NONX/对应游戏/` 运行 `一键导入.cmd` 或 `一键取消导入.cmd`。脚本按自身位置寻找项目，允许改变盘符、用户名和项目文件夹名称。若已经导入过模型，迁移时同时保留 `models/NONX/`、对应 `profiles/NONX-*.json` 和 `.nonx-imports/`，后者是撤销所需的相对路径记录。详细说明见 [NONX 使用说明](NONX/README.md)。

适用：Windows 10 专业版 1903 或更新、Windows 11 专业版，x64。把整个 `ndi-yolo-viewer` 目录复制到新电脑；模型、串口诊断、手动测试、固件三段镜像、Python 3.12.10 官方安装包、Microsoft VC++ x64 安装包、离线 Python wheel，以及 `OBS/` 中的 OBS Studio 32.2.2 和 DistroAV 6.2.2 安装包都在目录内。不需要复制项目旁边的任何目录或旧 `.venv`。已有板卡可继续使用；新板卡需先按固件向导检查和备份。

1. 复制后运行 `install.cmd`。它先校验安装包、wheel 和模型的 SHA-256，再优先使用已有的 Python 3.12 x64；没有时把随附 Python 安装到本项目的 `runtime/python312`。不改变系统 PATH、文件关联或已有 Python。若系统缺少 VC++ x64 运行库，会请求管理员确认安装随附的微软签名安装包。随后在本目录建立 `.venv`、离线安装固定版本依赖、做不碰硬件的健康检查与模拟测试。若复制了不可用的旧 `.venv`，脚本保留它并另建新环境。
2. 检查 `install-report.json`：`imports` 应全为 `OK`，默认模型应显示输入和输出形状。`providers` 中有 `DmlExecutionProvider` 只能说明运行库可用；实际 GPU 推理还要在界面加载模型后确认。无兼容 DirectX 12 显卡或驱动时可在界面选 CPU，性能可能较低。[DirectML 最低要求](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html)为 Windows 10 1903 及 DirectX 12 设备。
3. 运行 `verify.cmd` 可重复校验离线文件和已装环境；运行 `simulate.cmd` 使用两张本地样本验证模型和红名识别。这两个入口都不碰板卡或 NDI。运行 `run.cmd` 启动识别软件；先刷新 NDI 来源，选实际 OBS 来源；新电脑的来源名、COM 编号可能不同。默认不连接串口、不移动或点击。`run-cf480.cmd` 只是预选对应模型配置。

安装失败时先看本目录 `logs/install-*.log` 和 `install-report.json`。不要只复制 `.cmd`：`installers/`、`wheels/`、`models/`、`OBS/`、`firmware-tool/firmware/`、`samples/`、三个板卡工具目录及项目根目录源码需一起保留。`.venv/`、`runtime/`、`model-reports/` 和历史测试输出不是运行必需品；备份与日志可能含设备身份或旧配置，迁移前自行决定是否私下保留。

## 板卡工具

| 入口 | 用途 | 是否会改动板卡 |
| --- | --- | --- |
| `start-diagnostics.cmd` | 端口、指定波特率、身份、统计、Makcu 查询、kmboxNet 握手和主机输入事件验收 | 只读诊断会打开串口并发送查询，可能切换软件输入所有者；复位、改速、单次输入是另需确认的独立按钮 |
| `start-serial-test.cmd` | 对 M 板做手动身份、统计、小位移和一次点击测试 | 连接/查询不会注入点击；移动/点击每次单独确认 |
| `start-firmware.cmd` | ESP32-S3 型号、MAC、Flash 大小与安全状态检查；整片备份、刷 v0.1.2、恢复备份 | 检查会让板子进入下载模式并短暂中断透传；擦除/写入必须先备份并输入板卡及 MAC 确认词 |

固件工具固定使用官方 HID-Bridge v0.1.2 的 bootloader、分区表和应用镜像，两块板烧同一份。无需 ESP-IDF，不自动下载或更新。**第一次处理新板时先隔离接线，只留当前板 COM；先检查型号/MAC/实际 Flash 和安全状态，再整片备份。** A/B 是人为标签，不是软件能从单板焊点自动识别的角色；背部 OTG 供电焊点也不能由程序检测。具体步骤和失败恢复见 `firmware-tool/README.md`。备份、MAC 记录和报告留在本机，不应随通用迁移目录传播。

隔离单板不能证明真实鼠标透传、M/P 角色协商、目标电脑消费 HID 报告或 kmboxNet 全部功能。烧录后断电，按板型核对：M 的 USB OTG 接真实鼠标，M COM 接控制电脑；P 原生 USB 接目标电脑；M GPIO17→P GPIO18、M GPIO18←P GPIO17、GND↔GND，不互接 5V/3.3V。新板型的供电和 OTG 焊盘必须先对照其原理图，不能照搬旧板焊法。双板接好后再用诊断工具和目标电脑空白窗口验收。

发送电脑先运行 `OBS/OBS-Studio-32.2.2-Windows-x64-Installer.exe`，再关闭 OBS 并运行 `OBS/distroav-6.2.2-windows-x64-Installer.exe`，最后在 OBS 配置 NDI 主输出。直接运行本项目的接收电脑不需要安装 OBS、DistroAV 或 NDI Tools：随附 `cyndilib` wheel 含本程序使用的 NDI 接收库。单机使用时两者装在同一台电脑。`install.cmd` 不会自动安装 `OBS/` 中的软件。1920×1080 游戏画面裁剪为中心 640×640 的具体设置及安装包签名情况见 [OBS使用说明](OBS使用说明.md)。两台电脑要在可发现彼此的网络，防火墙允许 NDI 通信。模型文件是否允许私人迁移或再分发由模型来源决定，不要把未知许可模型公开发布。

鼠标输出依赖 HID-Bridge v0.1.2 双板及正确接线。需手动选择 M 板当前 COM；串口只能由一个程序占用。GPIO4 试验开关不再被识别软件查询，也不再影响软件许可。`install.cmd` 和 `verify.cmd` 不打开串口、NDI 来源或发送 HID 输入。

注意：安装包离线固定版本不是自动安全更新；需要升级时重新验证兼容性。Windows Defender、防火墙、显卡驱动、OBS/NDI 发送配置和双板硬件状态不能由本项目离线安装器代办。安装器不保证“复制到任何电脑立即可用”，但会在缺文件、缺依赖、模型损坏和模拟测试失败时明确停止。新电脑的实际 NDI 接收、GPU 推理及鼠标透传仍需现场验收。
