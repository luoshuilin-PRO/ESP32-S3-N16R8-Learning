# OBS/NDI 当前版

## OBS 和 DistroAV 安装

本项目的 `OBS/` 目录现已包含以下两个 Windows x64 安装包：

1. `OBS/OBS-Studio-32.2.2-Windows-x64-Installer.exe`：先在画面发送电脑安装 OBS Studio 32.2.2。
2. `OBS/distroav-6.2.2-windows-x64-Installer.exe`：关闭 OBS 后安装 DistroAV 6.2.2，再启动 OBS，在「工具」菜单确认出现 DistroAV 设置。

本机检查确认两个文件存在；OBS 安装包数字签名有效，随附的 DistroAV 安装包未签名。打包迁移时保留整个 `OBS/` 目录；在新电脑运行安装包前，可与 [OBS 官方下载](https://obsproject.com/download) 和 [DistroAV 官方发布页](https://github.com/DistroAV/DistroAV/releases)核对版本及来源。`wheels/cyndilib-*.whl` 供本程序直接接收 NDI 视频，不能让 OBS 自动具备 NDI 发送功能。

直接运行本项目 `run.cmd` 的接收电脑无需安装 OBS、DistroAV 或 NDI Tools；只有需要在接收电脑的 OBS 中另行预览 NDI 时，才需安装 OBS 和 DistroAV。单机使用时，OBS 与本程序装在同一台电脑。`install.cmd` 只安装本项目的 Python 环境，不会自动运行 `OBS/` 中的安装包。

## 发送电脑：中心 640×640

以下数值适用于游戏画面为 1920×1080 且准星固定正中央的情况。分辨率改变时需重新计算裁剪量，不能沿用这些数值。

1. 在 OBS「源」中添加「游戏采集」，选择游戏窗口，先确认 OBS 预览有实时画面。若游戏采集无法正常显示，可改用「显示器采集」并选择游戏所在的显示器；使用显示器采集时，切出游戏也会把桌面或其他窗口送出。
2. 给采集源添加「裁剪／填充」滤镜：左、右各 640 像素，上、下各 220 像素。OBS「设置 → 视频」中的基础画布和输出分辨率均设为 640×640。调整来源的位置与大小，让中心裁剪画面填满画布，准星落在 (320,320)，四周没有黑边；不要只把完整 1920×1080 画面缩放到 640×640。
3. 在 OBS「工具」菜单打开 DistroAV 的 NDI 设置，启用 Main Output／主输出并给来源取名。若「工具」中没有 DistroAV，检查插件是否安装到当前 OBS 版本并重启 OBS。使用 NDI 主输出不需要点击 OBS 的「开始直播」。
4. 确认接收电脑能在本程序中发现该来源。双机需处于可互相发现的网络，Windows 防火墙需允许相应 NDI 通信。

## 接收电脑：本程序

将整个项目目录复制并完整解压后，先运行 `install.cmd`，再运行 `run.cmd`。点击「刷新来源」，选择发送电脑刚设置的 OBS 来源并连接；检查预览是否为完整的中心 640×640 画面，准星是否在 (320,320)。随后按所用模型配置加载模型并开始识别。新电脑上的来源名、COM 号可能变化，不沿用旧机器的选择。安装和迁移细节见 [迁移说明](迁移说明.md)。

关闭旧窗口后运行 run.cmd，刷新来源，选择 OBS PGM，连接并加载 cf.onnx（v5、类别 2），开始识别。OBS 输出为中心 640×640，准星位于 (320,320)。单机使用本机 OBS 来源；双机使用主机来源。

输出默认关闭，目标跟随默认未勾选。“仅红名触发（无需右键）”勾选后独立控制点击，可不加载模型直接开始颜色识别；取消勾选即不会自动点击。跟随每个新结果选择半径内最近的目标类别框，仅在真实右键按住时移动；F8 停止输出。

默认参数：按下 50ms、松开 100ms、旧帧 200ms、移动比例 0.05、步长上限 4、选择半径 150。已保存的 config.json 同步恢复这些数值。读取别处旧配置可能带回其他参数；修改参数后重新启用输出才生效。

「范围预设」选择「最大范围」会将移动比例改为 0.25、步长上限改为 10、半径改为 300；选择「默认」恢复 0.05、4、150。切换会立即停止输出，重新启用后参数生效。选择后仍可单独微调数值；保存配置会同时保存预设名称和实际参数。

保留 FP32/FP16 单输入单输出模型支持、auto/v5/v8/xyxy 布局检查、本地延迟 p50/p95 和物理按钮查询往返统计。推理循环和移动判定已恢复到打包版逻辑。格式有歧义时手动指定。模型加载兼容不代表认识所有游戏；头部类别及红名参数仍需匹配样本。

本地耗时不包含 OBS 上游、HID 和游戏响应；查询往返不是物理按钮到游戏的完整延迟。切出主机游戏前停止输出，当前没有主机窗口失焦检测。

本次恢复未打开串口或发送实际鼠标输入，未修改固件。旧迁移压缩包仍是独立副本，不会自动更新。

当前 `config.json` 是单独保存的用户参数，包含 0.25／10／300 和旧帧 220ms；打包版默认启动值为 0.05／4／150 和旧帧 200ms。恢复代码不覆盖用户保存的配置；要对比原版手感，可在界面选择「默认」预设并把旧帧设为 200ms，然后重新启用输出。

## 游戏配置与预览

「游戏配置」输入名称后点保存，会在 `profiles` 目录建立独立 JSON。选择已有配置并点切换，程序先停止识别与输出，再载入模型路径、类别、置信度、识别范围、红名参数和移动参数；随后手动点「加载」及「开始识别」。切换不自动打开 COM 或启用输出。原来的 `config.json` 保存／读取入口继续可用。

预览中的虚线圆圈显示当前选择半径；黄色头部框是准星范围内最近的 class=1 候选，绿色是其他检测框。左上角显示候选头部和红名命中状态。标记依据当前界面半径与最新结果，仅供调参观察；真实输出还要求物理右键、结果新鲜且已启用输出。界面调整半径后，运行中的输出仍使用上次启用时冻结的参数，需停止并重新启用才同步。
